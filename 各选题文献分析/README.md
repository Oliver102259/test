## 维护 SOP（三个场景）

### 场景一：新增文献报告（新报告 / 修改已有报告）

1. 精读完成后，把报告 Markdown 保存为 `D:\NUS311RA\文献精读-<文献短名>.md`（根目录，工作副本）。
2. 在 `D:\NUS311RA\文献分析流水线.sh` 的**课题映射表**中登记该文件名关键字 → 课题目录（若新课题）。
3. 运行流水线（含推送）：
   ```bash
   bash /mnt/d/NUS311RA/文献分析流水线.sh --push
   ```
   流水线自动完成：规范化 → 生成 front-matter（标题/日期/版本号自动递增）→ 转 Word → 按课题归档 → Git 推送。
   - 幂等：源未变化时自动跳过（增量）；`--force` 强制重转；不带 `--push` 只转换不推送。
4. （可选）验证 Pages 链接：`https://oliver102259.github.io/test/各选题文献分析/<课题>/文献精读-XXX.html`。

### 场景二：修改已有报告

1. 修改 `D:\NUS311RA\文献精读-<文献短名>.md`。
2. 重跑 `bash /mnt/d/NUS311RA/文献分析流水线.sh --push`——自动重转并递增版本号（V1.0→V1.1），覆盖同名 `.md/.docx`。
3. **工作台链接无需修改**（固定文件名 → 链接不变，内容自动更新）。

### 场景三：工作台「文献分析」专栏更新

1. **新增文献**：在专栏对应课题的表格中新增一行（文献英文名/中文名 + 报告链接）。
2. **链接变更**：直接改专栏中的链接；页面由 `bash /mnt/d/NUS311RA/推送工作台.sh` 推送（GitHub API 通道，与文献流水线的 Git 通道互不冲突）。

## 流水线脚本（doc-pipeline 思想实现）

`D:\NUS311RA\文献分析流水线.sh` 将 md-to-docx（转换）与 doc-pipeline（阶段化）方法论落地为八个阶段：

```
阶段0 环境检查 → 阶段1 扫描源报告 → 阶段2 课题映射 → 阶段3 增量判断(md5)
→ 阶段4 front-matter 版本管理 → 阶段5 规范化+转 docx → 阶段6 按课题归档
→ 阶段7 Git 同步推送 → 阶段8 汇总报告
```

- 转换器：`D:\NUS311RA\tools\md-to-docx-skill\`（pickle-an/md-to-docx-skill 中文增强版，已修复"标题编号被剥离"缺陷）
- 依赖：python-docx、git、`.github-token`（仅授权 Oliver102259/test 仓库，请勿外泄）
- 转换质量保障：Markdown 规范化（中文数字标题、表格修复等）+ docx 结构抽查（标题层级/表格/超链接）

## 同步通道说明

| 通道 | 用途 | 触发方式 |
|---|---|---|
| Git（`文献分析流水线.sh --push`） | 各选题文献分析/ 目录 | 每次新增/修改报告 |
| GitHub API（`推送工作台.sh`） | 工作台 index.html | 工作台内容更新 |
