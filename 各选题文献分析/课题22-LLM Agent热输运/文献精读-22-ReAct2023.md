# 文献精读报告：ReAct: Synergizing Reasoning and Acting in Language Models（ReAct：在语言模型中协同推理与行动）

> **元信息**：Shunyu Yao、Jeffrey Zhao、Dian Yu、Nan Du、Izhak Shafran、Karthik Narasimhan、Yuan Cao（普林斯顿大学 / Google Research Brain）｜ICLR 2023（会议论文）｜arXiv:2210.03629v3（PDF 内可见，R0）｜精读日期 2026-08-21
> 证据分级：R0=原文事实（附页码/章节锚点）｜R1=外部背景知识｜R2=推断/评价

## 一、文献速览总结

**一句话定位**：这是提出 **ReAct（Reason + Act）** 范式的原始论文，把 LLM 的"推理"（chain-of-thought）与"行动"（调用工具/环境）以交错方式（thought–action–observation）统一起来，是课题 22 构建"LLM Agent 自动化热输运计算"的范式基石。

**核心内容**（R0）：ReAct 把智能体的动作空间从 A 扩充为 Â = A ∪ L，其中 L 是"语言空间"，L 中的动作即"想法（thought）/推理轨迹"——它不改变外部环境、不产生观测反馈，而是对当前上下文推理并更新上下文，以支持后续推理或行动（p.3，Sec.2）。想法有多种用途：分解任务目标、注入常识、从观测中抽取关键信息、跟踪进度并切换计划、处理异常并调整计划、改写检索词、综合最终答案（p.3）。

**主要结论**（R0）：
1. **ReAct 显著优于"只行动"（Act）**：在 HotpotQA 与 FEVER 上均优于 Act；在 ALFWorld 上 71% 平均成功率 vs Act 45% / BUTLER 37%，WebShop 上比次优绝对高 10%（p.5、p.8）。
2. **ReAct 比 CoT 更"事实可信"**：CoT 是"静态黑箱"，易产生事实幻觉与错误传播；ReAct 通过外部交互更 grounded，成功态幻觉率 6% vs CoT 14%，失败态幻觉率 0% vs CoT 56%（p.5-6，表 2）。
3. **最佳方案是"ReAct 与 CoT-SC 结合"**：让模型按启发式规则在二者间切换（p.5，表 1）。
4. **微调可进一步释放潜力**：仅 3000 条轨迹微调后，PaLM-8B 微调的 ReAct 超过所有 62B 提示方法、PaLM-62B 微调超过所有 540B 提示方法（p.6）。

## 二、课题关联分析

本文是课题 22 的"方法论定义"文献，与 Togo 2023（声子工作流）形成完美互补：

- **直接给出 Agent 的行为范式**：课题 22 要 LLM Agent 自动化"uMLIP + Phonopy/phono3py"热导工作流。ReAct 的交错 thought–action–observation 恰好映射为：thought（判断该跑哪一步、参数对不对）→ action（执行 phonopy 命令、提交 phono3py 任务）→ observation（读取 band.yaml / κ 结果 / 虚频告警）。Togo 2023 第 7 章的 6 步工作流可直接变成 ReAct 的动作空间（R2）。
- **"异常自动转人工"的范式来源**：ReAct 的 thought 用途明确包括"handle exceptions and adjust action plans"（处理异常并调整计划，p.3）与"track progress"（跟踪进度）。课题 22 要求"异常自动转人工"，正是把 ReAct 的"异常处理 thought"落到具体阈值判据（虚频、LBTE/RTA 异常、uMLIP 非保守力误差等，见 Togo/Loew 报告）上（R2）。
- **可解释性与人工可控性**：ReAct 强调"human interpretability, trustworthiness, diagnosability"，甚至支持"thought editing"让人中途纠正 Agent（p.2、p.4、图 5）。这对毕设的演示与答辩（可追溯每一步决策依据）是直接卖点。
- **与 7 志愿整体**：ReAct 是通用 Agent 范式，志愿 22/47/23/24 等任何"LLM 驱动计算"类课题都可复用；对志愿 50/39/70 这类偏实验/合成的方向，ReAct 的"检索+推理+行动"模式同样适用于文献调研与实验决策。

## 三、内容深度解读（按论文结构）

**1. 引言（p.1-2，Sec.1）**
人类智能的独特之处在于把"面向任务的动作"与"言语推理（内在言语）"无缝结合，用于自我调节、策略化与维持工作记忆（p.1，引用 Alderson-Day & Fernyhough、Vygotsky、Luria 等）。作者指出：现有 LLM 的"推理"（CoT）是**静态黑箱**，不 grounded 于外部世界，导致幻觉与错误传播；而"行动"类工作（WebGPT、SayCan、Inner Monologue）只用语言先验预测动作，不做抽象高层推理、不维持工作记忆（p.2）。ReAct 的贡献是二者协同（p.2-3）。

**2. ReAct 范式（p.3-4，Sec.2）**
形式化：t 时刻智能体收到观测 o_t，按策略 π(a_t|c_t) 选动作，上下文 c_t=(o₁,a₁,…,o_{t-1},a_{t-1},o_t)。ReAct 把动作空间扩为 Â=A∪L；L 中的"想法"不触发观测，而是把新信息写入上下文 c_{t+1}=(c_t, â_t)（p.3）。实现上用**冻结的 PaLM-540B**，few-shot（1–6 个 in-context 例子）生成"领域动作 + 自由文本想法"；知识密集任务用密集想法（多步 thought–action–observation 交替），决策任务让模型自己决定想法的稀疏出现（p.3-4）。四大特性：A) 直观易设计（人类标注者只需在动作之上写下想法，无专门格式/示例选择）；B) 通用灵活；C) 高性能且鲁棒；D) 人类对齐且可控（可 thought editing 实时纠正）（p.4）。

**3. 知识密集推理任务（p.4-6，Sec.3）**
- **设置**（Sec.3.1）：HotpotQA（多跳 QA）与 FEVER（事实核查），question-only 设置（不给支持段落）。动作空间为简化 Wikipedia API：search[entity]（返回条目前 5 句）、lookup[string]（模拟 Ctrl+F）、finish[answer]（p.4）。
- **基线**（Sec.3.2）：Standard、CoT、CoT-SC（自洽采样 21 条取多数）、Act（去掉想法，类似 WebGPT）（p.5）。
- **结果**（Sec.3.3，表 1）：HotpotQA EM——ReAct 27.4 略低于 CoT 29.4，但 ReAct→CoT-SC 35.1 最高；FEVER Acc——ReAct 60.9 > CoT 56.3，CoT-SC→ReAct 64.6 最高（p.5）。失败模式分析（表 2）：CoT 的主要失败是**幻觉（56%）**，ReAct 为 0%；但 ReAct 因"交错约束"降低了推理灵活性，产生 47% 推理错误（含"重复生成之前的想法/动作、跳不出循环"这一 ReAct 特有模式），另有 23% 因检索结果无信息而偏离（p.6）。
- **内部+外部知识结合**（p.5）：ReAct→CoT-SC（ReAct 步数超限则退回 CoT-SC）与 CoT-SC→ReAct（多数答案出现 <n/2 次则退回 ReAct）。
- **微调**（Sec.3.2，图 3）：用 3000 条正确轨迹自举微调，ReAct 从提示法的最差变为微调法的最优（p.6）。

**4. 决策任务（p.7-8，Sec.4）**
- **ALFWorld**：合成文本游戏，6 类任务，需长程规划（可 >50 步），考验常识定位物体。ReAct 平均 71%（best of 6），Act 45%，BUTLER（用 10⁵ 条专家轨迹的模仿学习）37%；ReAct 相对 Act 在 6 组受控试验中增益 33%–90%、平均 62%（p.8，表 3）。
- **WebShop**：118 万商品的网购环境，需按用户指令选品。ReAct score 66.6 / SR 40.0，Act 62.3/30.1，IL 59.9/29.1，IL+RL 62.4/28.7；专家人类 82.1/59.6（p.8，表 4）。
- **内部推理 vs 外部反馈消融**（p.8）：ReAct（71%）显著优于 IM 式（Inner Monologue 式密集外部反馈）提示的 ReAct-IM（53%），说明高层目标分解与常识推理是 IM 所缺的关键。

**5. 相关工作与结论（p.9-10，Sec.5-6）**
相关工作覆盖 CoT 系（least-to-most、zero-shot CoT、self-consistency、STaR、Scratchpad）与决策系（WebGPT、SayCan、Inner Monologue、BlenderBot/Sparrow）（p.9）。结论强调：ReAct 简单有效、可解释；局限是复杂大动作空间任务需要更多示例、易超 in-context 长度，未来可结合多任务训练与强化学习（p.9-10）。

## 四、技术难点识别

1. **幻觉 vs 推理错误的权衡**（R0）：CoT 幻觉率高、ReAct 推理错误率高（含死循环），二者需结合（表 2）——课题 22 的 Agent 若只用纯 ReAct，可能陷入"重复执行同一命令"的循环，需显式防环与步数上限（R2）。
2. **检索质量决定成败**（R0）：23% 失败源于"搜索无信息"，一旦偏离难以恢复（p.6）——对应到计算 Agent，即"读不到关键输出/日志解析失败"会拖垮流程，需健壮解析与重试策略。
3. **提示法的规模瓶颈**（R0）：大动作空间需更多示例、超上下文长度（p.9）；微调可缓解但需高质量标注（p.6）——课题 22 的动作空间（数十条 phonopy/phono3py 命令 + 参数）中等复杂，需精心设计 few-shot 示例或考虑微调。
4. **安全与可控**（R0）：LLM 接入外部环境有风险（p.10，Ethics）——计算 Agent 应限制在沙箱内、命令需白名单化（R2）。

## 五、可借鉴点

- **范式模板直接套用**：课题 22 的每次循环 = Thought（判断 + 计划）→ Action（跑 phonopy/phono3py 命令）→ Observation（读输出/日志），与 ReAct 完全同构。
- **thought 类型清单**（p.3）：目标分解、常识注入、观测抽取、进度跟踪、异常处理、计划调整、综合结论——可直接作为 Agent 提示词里"thought 应该写什么"的指引。
- **结合 CoT-SC 的策略**（p.5）：当 ReAct 步数超限或无把握时退回"纯推理自洽采样"，可借鉴为"Agent 卡住时退回人工/保守路径"的兜底机制。
- **thought editing / 可诊断性**（p.4、图 5）：在毕设里实现"人工可查看并干预 Agent 每一步 thought"，既是"异常转人工"的界面，也是答辩演示亮点。
- **微调路线**（p.6）：若 few-shot 效果不足，用少量正确轨迹自举微调是低成本提升路径，与课题 22"异常转人工积累标注数据"天然契合（R2）。

## 六、延伸思考

- ReAct（2023）是"提示范式"；MatClaw（2026）等后续工作走向"代码优先 + 端到端"的 Agent（见配套报告），课题 22 可定位在两者之间：用 ReAct 的推理-行动闭环，但把"行动"做成可执行、可版本化的代码片段（R2）。
- 本文的"语言空间 L 不产生观测"这一设计，暗示"纯推理"与"工具调用"的分离；在科学计算 Agent 中，可以把"推理"放在 LLM、把"确定性计算"放在 phonopy/phono3py，二者以文本观测桥接，正是课题 22 的架构本质（R2）。
- 失败模式表（表 2）提示：Agent 的可信度不能只看最终结果，还要看"推理轨迹是否 grounded"；毕设报告应同时呈现"决策依据可回溯"这一 ReAct 核心价值。
